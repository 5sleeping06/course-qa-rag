# 第 3 章 TCP 连接管理（示例资料，仅用于跑通链路）

## 三次握手

TCP 建立连接需要三次握手。客户端先发送 SYN 报文，携带自己的初始序列号；服务端收到后回复 SYN+ACK，
既确认客户端的序列号，也带上自己的初始序列号；客户端再发送 ACK 确认。至此双方都确认了对方的收发能力。

为什么不是两次：如果只握手两次，服务端无法确认客户端是否收到了自己的确认报文。更关键的是，
网络中可能存在早已失效的连接请求报文段，若它延迟到达服务端，两次握手会让服务端直接建立连接并分配资源，
造成资源浪费甚至错误连接。三次握手让客户端有机会拒绝这种历史连接。

## 四次挥手与 TIME_WAIT

TCP 是全双工的，断开连接时一方发送 FIN 只表示自己不再发送数据，仍可接收，此时处于半关闭状态，
所以需要四次挥手。

主动关闭方在发送最后一个 ACK 后进入 TIME_WAIT 状态，需要等待 2MSL。原因有两个：
一是保证最后一个 ACK 能到达对端，如果对端没收到会重发 FIN，此时还能重发 ACK；
二是让本次连接产生的所有报文段在网络中消失，避免影响后续使用相同四元组的新连接。
